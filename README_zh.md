# Codexia

[English README](README.md)

## 项目介绍

Codexia 是一个 Windows 桌面应用，用于在 Codex 中集中使用 ChatGPT 订阅账号和第三方模型渠道。

![Codexia 概览](docs/screenshots/overview.png)

## 为什么使用

- 将 ChatGPT 订阅账号转换为本地 API 服务。
- 通过 Responses API 渠道接入第三方模型。
- 直接在 Codex 的模型列表中轻松切换订阅模型和第三方模型。
- 在同一个桌面应用中集成并管理可选的 MCP 服务。
- 快捷查看并使用订阅账号可用的重置卡。
- 根据各模型的输入、缓存输入和输出费率估算调用成本。
- 可选地让账号模式请求通过 API 服务代理，并将 Responses 调用纳入调用分析。

## 快速开始

1. 打开 `Codexia.exe`。
2. 添加 ChatGPT 订阅账号、模型渠道，或同时添加两者。
3. 打开“接入模式”并应用 API 模式。
4. 在“服务管理”中启动 API 服务。
5. 回到 Codex 选择模型。

API 模式可以同时使用订阅模型和第三方模型；账号模式使用一个选中的订阅账号，并可选择是否通过 API 服务代理。

## 功能与设置

### 订阅账号

可以通过浏览器登录，也可以导入 Codex 当前使用的账号。应用支持查看额度和重置次数、刷新账号、启用或停用账号、使用可用的重置次数，以及删除账号。

### 模型渠道

每个 Responses API 渠道支持以下设置：

- 渠道名称、API 地址、API Key 和启用状态。
- 渠道提供的 Codex `models.json`；不同渠道的模型 ID 不能重复。
- WebSocket 支持；仅支持 HTTP 的渠道应保持关闭。
- 远程压缩适配；除非渠道明确支持 Codex 原生压缩，否则建议保持开启。
- 可选的余额查询、普通或加密请求头，以及各模型的输入、缓存输入和输出费率。

内置订阅渠道还提供可选的 Codex Bundled 覆盖，默认关闭；启用后，手动填写的模型 JSON 会替代 CLI 内置目录，再与第三方模型合并生成最终 `models.json`。

使用渠道前，可以查看导入的模型目录并运行调用测试。

“接入模式”用于将 API 模式或账号模式应用到 Codex。应用 API 模式前，还可以选择推荐的 Base URL 配置或自定义 Provider 配置。账号模式可勾选“通过 API 服务代理”；应用后会启动现有 API 服务并写入其 `/v1` Base URL。账号凭证会原样转发到 ChatGPT Codex 后端，只有 HTTP 与 WebSocket `/responses` 写入调用分析，其他路径仅透明转发，也不写调试 JSONL。设置 `CODEX_HOME` 环境变量后，Codexia 会从该目录读写 Codex 配置；未设置时使用当前用户默认的 `.codex` 目录。

### 服务管理

“服务管理”用于启动、停止或重启本地 API 服务，以及由 [`mcp-gateway-service`](https://github.com/jadchene/mcp-gateway) 提供的可选 MCP 服务。账号模式开启代理后同样使用现有 API 服务，不增加独立服务或端口。启动 MCP 服务前，需要先配置文件路径和服务地址。

### 会话唤醒

在“会话唤醒”中登记 Codex 会话 UUID，选择包含日期的生效时段和最大尝试次数。请保持 Codexia 和对应的 Codex 会话运行，确保本机 `codex` 命令可用，且 Codexia 使用与该会话一致的 `CODEX_HOME`。

订阅账号池请求因额度不足失败、且无法切换到其他账号时，Codexia 会等待最近的额度重置时间，再留出一分钟后刷新账号额度。本次刷新成功且确认有可用额度才会唤醒；没有未来重置时间时，每五分钟检查一次。支持 HTTP、SSE 额度错误及 WebSocket；第三方渠道错误和账号模式透明代理请求不触发账号池唤醒。

开启“恢复 Goal”后，通过 Codex app-server 控制协议恢复未完成的原目标，无需加载会话；已完成的目标不会重新激活。关闭时或会话没有 Goal 时，通过 `codex queue` 发送继续消息。需要 CLI 支持这些能力，已在 0.154.0 验证。

每轮额度检查及后续唤醒合计一次尝试，失败也计数；次数在整个生效时段内累计，成功后不清零，修改会话或生效时段开始新的计数。停用、删除或到期后停止自动唤醒。等待进度会保存到本地数据库，重启应用后恢复；如果应用在投递消息期间退出，该记录会提示人工确认，不会自动重复发送。

### 定时任务

在“定时任务”中填写已有会话 UUID，或选择“每次新建会话”并填写已存在的完整工作目录。配置消息内容、生效起止日期时间、五段 Cron 表达式和启用状态。Cron 按本机时区执行：`0 * * * *` 为每小时，`0 22 * * *` 为每天 22 点，`0 9 * * MON` 为每周一 9 点。

可通过生成器选择分钟步长、每小时、每天或每周的执行时间，再点击“生成表达式”，也可以直接编辑 Cron。分钟步长在每小时内计算。

已有会话通过 `codex queue` 接收普通消息，`/goal resume` 等斜杠命令也只作为文本传递。新会话通过 `codex exec` 执行，使用工作区沙箱和自动审批复核，并在列表中记录最近的会话 ID 和执行结果。请保持 Codexia 运行，并使用与目标会话一致的 `CODEX_HOME`。

生效时段约束新的触发，停用或删除任务不会取消已经开始的执行。同一任务不会重叠运行，最多同时执行四个定时任务。重启或长时间休眠后跳过错过的时间点，不集中补发；失败会显示在列表中，等待下一个 Cron 时间点，不在同一时间点反复发送。退出 Codexia 会停止它启动的新会话进程；重启后不自动重跑上次中断的那一轮。

### 设置

| 区域 | 可配置内容 |
| --- | --- |
| 常规 | 开机自启、关闭窗口时的行为、界面主题和显示密度。 |
| API 服务 | 监听地址、端口、访问密钥、服务自动启动，以及可选的 API 调试请求/响应日志。 |
| MCP 服务 | 未安装提示、自动启动、配置文件路径、主机、端口和 HTTP 路径。 |
| 账号与额度 | 自动刷新间隔、刷新超时、账号选择策略、滑动 Session 亲和有效期、账号失败冷却、额度显示，以及自动审查使用的可选第三方回退模型。 |
| 日志与计费 | 调用记录保留时间、运行日志保留时间和计费币种。 |
| 存储 | 当前数据位置，以及清空调用记录或运行日志。 |
| 高级网络 | 连接和空闲超时、请求超时、停机宽限、HTTP 与 WebSocket 数量限制、请求与缓冲区大小限制，以及仅支持 HTTP 的模型自动回退。日常使用建议保持默认值。 |

部分服务设置需要重启对应服务后生效。

### API 调试日志

默认关闭（设置 > API 服务）。开启时会显示敏感数据警告，HTTP 与 WebSocket 的 API 请求和响应会以 JSON Lines 格式记录到 `data/logs/<yyyymmdd>.jsonl`；账号代理模式只记录 `/responses`。敏感请求头自动脱敏，但正文会保留以便排障，每条最多记录 1 MiB。调试模式最多开启 10 分钟，手动关闭、到期自动关闭或退出应用时都会删除全部调试日志。

### 数据与备份

正式版数据保存在应用旁边的 `data/` 目录中。移动或替换应用前请备份该目录。目录中包含账号和渠道配置，请勿分享。

`data/backups/` 下的自动数据库结构迁移备份会进行整文件加密：每个备份使用独立的 AES-256-GCM 数据密钥，并由 Electron `safeStorage` 封装该密钥，因此备份与创建它的 Windows 用户安全上下文绑定。旧版本留下且尚未过期的明文迁移备份会在下次启动时自动加密；迁移备份保留 24 小时后自动删除。

本项目用于个人本地使用。请使用自己的账号和 API Key，并遵守各服务提供方的条款。

## 开发

需要 Node.js 24 或更高版本。

```bash
npm install
npm run dev
npm run verify
```

生成 Windows 免安装包：

```bash
npm run pack:unpacked
```

输出文件为 `release/win-unpacked/Codexia.exe`。该程序未进行代码签名，也不包含安装器。
